# Токен бота убран из кода сайта + починена запись заказов в таблицу

## Было две отдельные проблемы

1. **Токен Telegram-бота лежал прямо в `index.html`** — его видел любой,
   кто открывал «Просмотр кода страницы». Отсюда и фишинг в вашем чате.
2. **Заказы не попадали в таблицу `order`.** Причина: старый `index.html`
   вообще не обращался к вашему `Code.gs` — он слал заказ напрямую в Telegram
   API с браузера пользователя, в обход таблицы. Скрипт с `sheet.appendRow(...)`
   был написан правильно, но сайт его просто никогда не вызывал.

## Что исправлено

- `index.html` теперь отправляет POST-запрос на ваш Apps Script (`ORDER_API_URL`)
  с полями `name, phone, address, items, payment, total` — именно теми, что
  ожидает ваш `doPost` — плюс поле `text` с готовым текстом для Telegram.
- `Code.gs` дополнен: после записи строки в таблицу `order` он сам отправляет
  уведомление в Telegram, используя токен, который хранится **на сервере**
  (Script Properties), а не в коде сайта.
- Если Telegram-уведомление почему-то не отправится (например, токен ещё не
  настроен) — заказ всё равно запишется в таблицу, это отдельная операция и
  друг друга они не блокируют.
- В таблицу теперь также попадает ссылка на точную геолокацию клиента (если
  он воспользовался кнопкой 📍) — прямо в колонке адреса.

## Диагностика: «пишет что заказ отправлен, но никуда не приходит»

Раньше приложение показывало «Заказ отправлен администратору» **независимо
от того**, прошёл ли запрос на сервер успешно — оно не проверяло ответ.
Теперь это исправлено: если сервер не ответил, ответил ошибкой, или в таблицу
ничего не записалось — вы увидите чёткое сообщение об ошибке с технической
причиной вместо ложного «успеха». Сделайте тестовый заказ ещё раз — текст
ошибки в алерте сразу подскажет, что не так. Ниже — расшифровка типичных причин.

### 1. `ORDER_API_URL` всё ещё содержит плейсхолдер
Откройте `index.html`, найдите:
```js
const ORDER_API_URL = 'https://script.google.com/macros/s/ВАШ_ORDER_DEPLOYMENT_ID/exec';
```
Если там до сих пор `ВАШ_ORDER_DEPLOYMENT_ID` — это стопроцентная причина.
Вставьте туда реальный URL вашего нового деплоя (см. предыдущий шаг про
"New deployment").

### 2. Доступ к деплою не "Anyone"
**Deploy → Manage deployments** → у нужного деплоя должно быть указано:
Execute as: **Me**, Who has access: **Anyone**. Если стоит "Only myself" или
"Anyone within [организация]" — запросы с сайта будут получать отказ в доступе.

### 3. Скрипт не прошёл повторную авторизацию
Раз в `doPost` добавился новый внешний вызов (`UrlFetchApp.fetch` к Telegram),
Google иногда требует заново подтвердить разрешения. Откройте редактор Apps
Script, выберите функцию `doPost` в выпадающем списке вверху и нажмите ▶ Run
вручную один раз — появится запрос на подтверждение прав, подтвердите его.
После этого сделайте новый деплой (New version).

### 4. Название листа не совпадает
`doPost` ищет лист с именем ровно `order`. Откройте таблицу и проверьте
название вкладки внизу — если оно отличается (например `Order`, `orders`,
`Заказы`), либо переименуйте вкладку в `order`, либо поменяйте `'order'`
в `Code.gs` на точное название.

### 5. Смотрите Executions в Apps Script
Это самый надёжный способ. В редакторе Apps Script слева — значок часов
⏱ **Executions**. После тестового заказа там появится запись о вызове
`doPost` — откройте её и посмотрите, есть ли ошибка и какая именно.
Это покажет причину точнее любых догадок.

## Что нужно сделать вам, если настраиваете с нуля
Старый токен уже был публично виден в коде и, судя по фишингу в чате, уже
известен мошенникам. В Telegram: **@BotFather** → `/mybots` → ваш бот →
**API Token** → **Revoke current token**. Скопируйте новый.

### 2. В Apps Script откройте «Свойства скрипта»
⚙️ **Настройки проекта** → **Свойства скрипта** → добавьте:

| Свойство | Значение |
|---|---|
| `TELEGRAM_BOT_TOKEN` | новый токен из шага 1 |
| `TELEGRAM_CHAT_ID` | ваш chat_id (например, тот же `7567253745`, если это верный чат) |

### 3. Замените код в вашем Apps Script проекте
Вставьте содержимое обновлённого `Code.gs` (замените целиком старый файл —
он использует тот же `SPREADSHEET_ID`, ничего не потеряется).

### 4. Разверните новую версию
**Deploy → Manage deployments** → у существующего деплоя нажмите ✏️
(редактировать) → **Version: New version** → **Deploy**.
(Если создадите совсем новый деплой вместо обновления старого — поменяется
URL, и его нужно будет заново вписать в `index.html`.)

### 5. Проверьте название листа
`doPost` ищет лист с именем ровно `order` (все строчные). Если у вас вкладка
называется, например, `Order` или `Заказы` — либо переименуйте вкладку в
`order`, либо поменяйте `'order'` в `Code.gs` на точное имя вашей вкладки.

### 6. Оформите тестовый заказ
После деплоя сделайте тестовый заказ на сайте и проверьте:
- появилась ли строка в таблице `order`;
- пришло ли сообщение в Telegram.

Если что-то не сработало — в Apps Script откройте **Executions** (⏱ значок
слева) и посмотрите на ошибку в логе последнего запуска `doPost`.
